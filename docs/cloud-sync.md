# 存檔同步（Cloud Sync）使用說明

這份說明給多裝置輪流玩同一批遊戲的人（例如 Windows 與 iPhone）。同步用的是 WebDAV，
只同步存檔（`saves/`，PS1 / MD 的 `.srm`、記憶卡等）；預設不同步 states 與設定檔。

## 一、預防：換裝置前先同步

**規則：離開一台裝置之前，確認它已經同步完成；到另一台裝置玩之前，先讓它同步一次。**

- 同步模式是「自動」：RetroArch **啟動時**與**關閉遊戲（卸載 core）時**各同步一次。
- 關掉遊戲後，不要馬上結束 RetroArch。等畫面上出現「Cloud Sync finished」再離開。
  上傳是背景進行的，太快結束程式可能來不及上傳，要等下次開機才補傳。
- 換到另一台裝置時，先打開 RetroArch 等它同步完，再開始玩。

為什麼：WebDAV 沒有版本歷史，伺服器上只有一份。兩台裝置各自改過同一個存檔，
而且都還沒同步時，程式沒辦法判斷哪一份才是你要的，這就是「衝突」。

## 二、衝突時會發生什麼

程式**不會自動覆蓋、也不會刪除**任何一邊。它會：

1. 兩邊的原檔維持不變（裝置上的檔案、伺服器上的檔案都不動）。
2. 把兩邊的版本各複製一份備份，放在**核心資源資料夾**（`core_assets_directory`，
   Windows 版預設是 RetroArch 目錄下的 `downloads\`）底下的 `cloud_sync_conflicts\`：

   ```
   <核心資源資料夾>\cloud_sync_conflicts\saves\<core名稱>\
       <遊戲名>.conflict-local-<日期>-<時間>.srm     ← 這台裝置的版本
       <遊戲名>.conflict-server-<日期>-<時間>.srm    ← 伺服器的版本
   ```

   這個資料夾在 `saves/` 以外，不會被同步出去。同一個衝突重複同步時，內容相同的備份不會重複產生
   （以 MD5 判斷）。
3. 同步結束時標題會顯示 **Cloud Sync finished with conflicts**，並跳出訊息，
   告訴你備份放在哪裡。每次同步，只要衝突還在，就會再提醒一次。

備份失敗（例如磁碟寫不進去、伺服器版本下載失敗）不影響上面第 1 點：原檔照樣不動。

## 三、怎麼處理：在選單選「以哪一邊為準」

**設定 → 雲端同步 → 解決同步衝突**（英文介面：Settings → Cloud Sync → Resolve Sync Conflicts；
iPhone 的 MaterialUI 也是同一個位置，點一下即可）。

1. 列表顯示上一次同步發現有衝突的檔案。點一個檔案。
2. 選 **以本機為準**（用這台裝置的版本取代伺服器的版本）或 **以伺服器為準**（用伺服器的版本取代這台的版本）。
3. 確認頁會寫明**哪一邊會被取代**，以及備份位置。按「確定取代」才會動手；按「取消」什麼都不改。
4. 確認後會立刻同步一次，只處理這一個檔案；其他衝突的檔案不受影響。結果會用通知顯示。
   處理完該檔案就不再警告。

動手之前，被取代的那一邊一定先備份（見上面的 `cloud_sync_conflicts\`），選錯了可以拿回來。
備份失敗的話，「以伺服器為準」會停下來、什麼都不改；「以本機為準」會照做，因為伺服器版本在發現衝突時已經備份過。

幾種特殊情形：

- **本機已刪除、伺服器有新版本**：選「以本機為準」會**刪除伺服器上的檔案**（確認頁會寫明）；
  選「以伺服器為準」會把檔案下載回來。
  這種衝突只有發現它的那一次同步會警告，下一次同步預設會把檔案下載回來，所以要處理請趁早。
- **伺服器上的檔案已經不在（`manifest.server` 還有紀錄）**：選「以本機為準」會直接上傳，補回伺服器的檔案；
  選「以伺服器為準」會提示「伺服器上沒有檔案可下載，什麼都沒有改變」，本機的檔案不會被動到，
  這個檔案仍然列在衝突清單裡。
- **伺服器的紀錄是已刪除、本機有修改**：選「以伺服器為準」會刪除本機的檔案（先備份）。

### 沒有選單時（備援）：手動複製備份

先打開 `cloud_sync_conflicts\` 的兩份備份，確認你要留哪一份。

- 留「伺服器的版本」：結束 RetroArch，把 `*.conflict-server-*.srm` 複製到 `saves\<core名稱>\`，
  改成原本的檔名覆蓋存檔，再同步一次。
- 留「這台的版本」：先照上面做一次（用 server 版覆蓋、同步），再把 `*.conflict-local-*.srm`
  複製回去覆蓋、再同步一次，這台的版本就會上傳。
- 兩邊都想留：備份放著不動就好（備份不會被同步，也不會被自動刪除）。

## 四、一種常見的特例：伺服器檔案手動刪除了

如果你在伺服器上手動刪了某個 `.srm`，但 `manifest.server` 裡還留著它的紀錄，
裝置可能會判成衝突（本機沒有同步紀錄、或本機與紀錄內容不同）。
這時備份資料夾裡只會有這台的 `conflict-local` 版本（伺服器沒有檔案可以備份，日誌會有一行下載失敗的警告，屬正常）。處理方式見上一節「選單」。


## 五、不要這樣做

- 不要在兩台裝置**同時**玩同一個遊戲並存檔。
- 不要直接刪掉 `manifest.local` / `manifest.server` 來「重設」，那會讓更多檔案被判成衝突。
- 不要把 `cloud_sync_conflicts\` 放進 `saves\`（預設位置不會有這個問題，改過 `core_assets_directory`
  的人要注意）。
